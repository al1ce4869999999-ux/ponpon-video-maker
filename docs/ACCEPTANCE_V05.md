# v0.5 最終受入検証計画
更新: 2026-10-18

## 安全条件
- main / 公開アプリには変更を出さない。既存プロジェクトを消去しない。
- 画像原本を保持し、テストでは複製のみを使用する。
- CIで通っても、iPhone実機と正式素材の品質評価は未完了とする。

## A. 旧作業コミット照合
1. `e0fbb10` をgit object、ブランチ、PR、作業バックアップから探す。
2. 発見時は `git diff` で現HEADとの差分を精査。改変や強制pushは行わない。
3. 原本不在なら一致を宣言しない。機能別にテストで代替検証し、未照合記録を残す。

## B. Safari互換性
1. Linux WebKitの自動操作（リグ作成、画像登録、数値編集、ポインタ、モーション、JSON復元）をCI化する。
2. WebKit系環境でファイル読込・IndexedDB・Canvas・MediaRecorderの対応状況を記録。
3. 実機iPhone Safariで端末写真/ファイル素材の選択、指ドラッグ、再生、戻る、保存/共有、動画書き出しを確認。
4. 画面回転、タブ中断、ストレージ不足時に既存作品を保持できるか確認。
5. 実機テストはユーザーのiPhoneを遠隔操作できないため、実機ログを取得した時点でのみ合格扱い。

## C. 正式素材の映像品質
1. 正式デザインの原本を特定して保存し、原本の改変は禁止する。
2. body/head/eye/mouth/ear/arm/tailの透過パーツが揃っているかを検査する。**漫画の1枚絵はパーツ分割済み素材ではない。**
3. 開眼/閉眼と口開閉素材を確かめ、透過周辺の欠け・背景残留・継ぎ目を目視検査。
4. idle/blink/talk/nod/surprise/cry/tail_wag/stumble/fall_backを同じキャラ・同じ画角で録画する。
5. 頭を動かしたとき目口が追従すること、耳としっぽが独立して動くこと、顔と胴が裂けないことを各モーションで判定。
6. 接地・重心・動き終わりの停止感・カットの前後継続を比較。ぎこちなければ合格扱いにしない。
7. 正式素材なしで作ったテスト用の図形や空パーツは、レンダラーの動作確認にしか使用しない。

## 判定
- 受入OK: 機能・動作映像・iPhone保存が再現可能な証拠つきで確認された。
- 条件付き: 自動テスト合格でもSafari実機か正式素材評価が欠ける。
- NG: データ消失・誤った姿・パーツ分離・実際に保存できない状態。
